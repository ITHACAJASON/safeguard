# Agent 生产动作护栏 · 采购审批 MVP

用于验证一条企业工作流能否在生产式权限边界内运行的本地原型。**不是生产安全认证，也不是通用 AI 安全网关。**

案例选用虚构上市制造企业。参考[美的集团年度业绩资料（港交所）](https://www1.hkexnews.hk/listedco/listconews/sehk/2026/0330/2026033001928.pdf)及[美的披露的供应商管理报告](https://www.midea.com/content/dam/midea-aem/ca/reports/midea-canada-forced-labour-report.pdf)理解制造采购背景。企业名称、人员、单据和权限均为虚构；不代表美的采用本原型、使用同一权限规则或存在任何安全问题。

## 启动

要求 Python 3.12，无第三方包。默认关闭外部模型，**不需要 API 密钥，也不会连接企业系统**。

```sh
mkdir -p state
AGENT_MODEL_PROVIDER=offline python3 app.py --port 8765 --db state/demo.sqlite3
```

用同一台电脑上的浏览器打开 `http://127.0.0.1:8765/`。服务只监听 IPv4 回环地址。本机上的其他进程也可以访问；内置演示角色不是生产身份验证，不应通过反向代理、端口转发或容器映射对外开放。数据库存于上面指定的位置，可用不同数据库文件独立演示；运行中的数据库不可当作样例提交至仓库。

## 怎么体验

1. 采购专员读取已分配的 PR-1001，或输入「读取采购申请 PR-1001」并检查生成的建议动作。提议不执行；由人点击执行。
2. 读取未分配的 PR-2002，应拒绝。选择发送正式采购单，应拒绝。原型不存在正式发送能力。
3. 发起 PR-1001 的导出请求；仅演示接收方 `ops@example.test` 有资格进入审批。等待期间没有导出。
4. 主管批准这一笔导出；返回采购专员使用同一个审批编号执行。批准限定原申请人、单据、文件版本、接收方和有效期；重复执行不接受。导出仅返回本地脱敏演示内容，不发邮件、不调用任何外部系统。
5. 切换审计员，按时间重建申请、决定、执行及所据规则。模型提示和密钥不属于审计记录。

## 什么属于产品核心

- **模型只建议，不授予权限。** 离线解析器与可选大模型都只能生成受限结构。
- **业务动作以确定性规则为准。** 角色、单据归属、审批范围和有效期由服务判断。审批使用与操作记录共享数据库事务。这一版模拟业务执行，不因模型意见生成审批权限。
- **合规复用动作证据。** 权限规则、审批记录和服务事件可用于回答「当时为何允许」，不是独立法律意见、认证或完整合规系统。

## 真实模型（可选）

设置 `AGENT_MODEL_PROVIDER=glm` 或 `AGENT_MODEL_PROVIDER=deepseek`，使用对应环境变量 `GLM_API_KEY` 或 `DEEPSEEK_API_KEY`。密钥在运行环境注入，不写入源码、数据库、聊天或 ZIP。开启后，只向选定提供商发送由程序生成的固定演示指令，不发送用户原话或业务内容；结果仍须符合本地合成样例。可用 `GLM_MODEL` 或 `DEEPSEEK_MODEL` 覆盖对应默认标识。这是外部模型接线验证，不是开放域业务理解验证。模型调用失败后不执行动作；离线模式仍可运行。外部模型联通性须在获配密钥后单独验收。

## 迁移与生产差距

移入用户指定 GitHub 仓库时，只迁移源码、测试与本文档，不携带数据库、密钥和生成物；迁移前先检查目标仓库、现有工程约定与默认分支。预览服务器和公开部署是两项不同操作。

进入客户的授权测试环境前，换成企业真实 SSO 和服务身份；让目标业务系统本身在所有相关动作路径执行授权；接入独立留存的审计、密钥管理、并发与容量方案、退出和恢复预案，并复测故障时的权限行为。MVP 演示角色可在 UI 切换，SQLite 日志不是防篡改证据，不能据此声称具备客户级隔离、可用性或审计保证。

## 验收命令

```sh
python3 -m unittest discover -s tests -v
```

测试会启动临时本地服务及单独数据库，不读取密钥、不使用真实业务数据。详细验证范围以交付时实际检查为准。
